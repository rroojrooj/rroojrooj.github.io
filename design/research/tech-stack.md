# Research: tech stack for a minimal GitHub Pages site

_Final report from a research agent, 20 October 2026. That environment's network blocked most personal domains, so most pages were read from their public GitHub source._

## Static site options for an academic GitHub Pages site (checked Oct 20, 2026)

I checked versions against git tags, the npm, RubyGems, PyPI and Go module registries, and the official docs repos. I did not write or change any project files.

One thing about the repo: its `redesign` branch already holds a plain HTML/CSS site (commit 70f7194). Its `deploy.yml` uses `actions/checkout@v4` and `JamesIves/github-pages-deploy-action@v4`, which push the built site to a `gh-pages` branch.

### Findings per option
- **Plain HTML/CSS:** nothing to install or build. Jon Barron's repo was updated Oct 16, 2026. It is one `index.html` plus a 141-line CSS file, with one `.bib` file per paper in `data/`. It has no dark mode.
- **Jekyll on GitHub's built-in build:** still Jekyll **3.10.0** via `github-pages` gem **232** (Aug 2024). The pages-gem repo's last commit was Nov 2024. Only approved plugins run, and `jekyll-scholar` (the BibTeX plugin) is not one of them.
- **Jekyll 4 through Actions:** Jekyll **4.4.1** (Jan 2025) has had no release in 21 months. minima is **2.5.2** (Sep 2024), and minima 3 never shipped. `jekyll-scholar` is at 7.3.0 (Jan 2026).
  - **al-folio v1.2** (Aug 2026) is heavier than before: 44 gems in its Gemfile, 23 workflows, and its build still installs ImageMagick, Python nbconvert and npm purgecss.
  - **academicpages v0.9** (Jun 2026) runs Jekyll 4.4.1 with about 7 plugins. Its publications are Markdown files generated by Python scripts.
- **Hugo:** latest is **0.168.0** (Oct 13, 2026). 90k stars, 211 open issues, releases come every few weeks.
  - Still 0.x: features are deprecated and later become errors (renames in 0.158–0.164; Node 22+ needed if you use Tailwind or PostCSS).
  - Code highlighting is built in, and `transform.ToMath` renders KaTeX math at build time with no JavaScript.
  - It has no BibTeX parser.
- **Hugo Blox:** the repo is now `HugoBlox/kit`, pitched as "AI builds it". The academic-cv template needs:
  - Hugo, Go modules pinned to unreleased commits, Node/pnpm, Tailwind 4 and Pagefind
  - Python for the BibTeX import workflow

  The project has gone through several renames and migrations (Academic, Wowchemy, Hugo Blox, kit). It has the same problem as al-folio.
- **Astro:** latest is **7.4.1** (Oct 19, 2026) and needs Node 22.22 or newer. Three major versions came out between Dec 2024 and Jun 2026 (5, 6, 7). Cloudflare acquired it in Jan 2026.
- **Eleventy:** latest is **3.1.7** (Oct 15, 2026); v4 is still alpha. A rename to "Build Awesome" was announced in Mar 2026 and reportedly paused, so its future name and direction are unclear.
- **Quarto:** 1.10 is the stable release (1.10.x patches through Oct 2026) and 1.11 is in pre-release. Posit funds it. It has about 1,900 open issues. The installer bundles Pandoc, Deno, Typst and Sass.
- **Zola:** latest is **0.23.6** (Sep 2026), 204 open issues, still pre-1.0. Its 0.23.0 release (Aug 2026) is described by the project as "probably the most breaking version": it moved to Tera v2 templates and removed shortcodes, so older themes no longer work. It parses BibTeX natively with `load_data(format="bibtex")`.
- **Others:**
  - **Zensical** (successor to Material for MkDocs, which went into maintenance mode in Nov 2025) is at 0.0.71 and built for documentation sites. MkDocs itself has had no release since Aug 2024. Skip both.
  - **RenderCV 2.8** turns a YAML file into a CV PDF and is worth considering for the CV.
  - The real 2026 trend is writing plain HTML with an AI coding assistant, which removes the main cost of option 1.

### Comparison

| Option | Build deps | Deploy to Pages | Markdown | BibTeX | Math | Rot risk (2–3 yrs untouched) |
|---|---|---|---|---|---|---|
| 1. Plain HTML | None | From a branch, no workflow | No (write HTML) | By hand; link `.bib` files | Native MathML or KaTeX 0.19 from CDN | **Very low** |
| 2a. Jekyll, GitHub's build | None (GitHub runs it) | From a branch | kramdown + rouge | No | Add MathJax yourself | Low, but stuck on old 3.10 |
| 2b. Jekyll 4 via Actions | Ruby + Bundler (al-folio: much more) | Actions | Good | jekyll-scholar | Yes | Medium to high (Ruby version drift broke the last site) |
| 3a. Hugo, own layouts | One Go binary | Actions | Good, highlighting built in | Not native (use CSL-JSON/YAML data file) | **KaTeX at build time** | **Low** if version pinned |
| 3b. Hugo Blox | Hugo + Go + Node + Tailwind (+ Python) | Actions | Good | Yes (Python import) | Yes | High |
| 4. Astro | Node 22.22+, large npm tree | `withastro/action@v6` | MD/MDX, Shiki | Do it yourself (citation-js) | remark/rehype plugins | High |

| 6. Quarto | Large bundled installer | `quarto publish gh-pages` or quarto-actions v2.2 | Pandoc, excellent | **Best** (reads `.bib` directly) | Built in | Medium |
| 7. Zola | One Rust binary | Actions or zola-deploy-action | Good | **Native** | KaTeX in the browser only | Low if pinned; upgrades are painful |

### Recommendation: plain HTML/CSS (Barron style)

This is what the `redesign` branch already does.
- **Fits the core needs:** a homepage, links, a CV PDF and a publication list change a few times a year.
- **Nothing to break:** no toolchain, lockfile or theme upstream, and no workflow if deployed from a branch. A dependency-free page from 2010 still renders today.
- **Dark mode:** `prefers-color-scheme` in CSS plus a small toggle script.
- **Math:** MathML now works in every major browser, or use KaTeX from a pinned CDN version.
- **Publications:** keep one `.bib` file per paper and link it, as Barron does, then edit the HTML list by hand. Write a small local script only if the list grows past about 40 entries.
- **Weak spot:** blog posts in Markdown. For a few notes, copy an HTML template page per post.

### Runner-up: Hugo with no third-party theme

Use 3–4 layouts you write yourself and pin `HUGO_VERSION` in the workflow. Choose this once a real Markdown blog with code and math appears.
- It is a single binary with no runtime dependencies.
- Highlighting is built in, and math is rendered at build time.
- It is the most active of these projects.
- Hugo's own docs keep a current GitHub Pages workflow.

For publications, export CSL-JSON from Zotero into `data/`. If generating the list straight from BibTeX matters most, Zola is the alternative because it reads `.bib` natively. Accept that its ecosystem is smaller and its upgrades break things.

Avoid Hugo Blox and al-folio: they repeat the same failure.

### Minimal structure for the recommended option
```
index.html         bio, links, publications, news
404.html
.nojekyll          publish files as-is, skip Jekyll
assets/css/style.css   light/dark theme variables
assets/js/main.js      optional theme toggle
assets/img/
files/cv.pdf
pubs/<key>.bib (+ PDFs)
notes/<post>.html  optional
robots.txt, sitemap.xml  optional
```

### Deploying to GitHub Pages
- **Preferred: deploy from a branch.** In Settings → Pages, set Source to "Deploy from a branch", pick `master` and `/ (root)`, and delete `deploy.yml`.
  - There are no action versions to bump. GitHub runs its own managed publish step.
  - To keep README and similar files off the site, move the site into `docs/` and pick `master` and `/docs` instead.
  - For a custom domain later, set it in Settings (this writes `CNAME`), add the DNS records, then tick "Enforce HTTPS".
- **If a build step comes later (for example Hugo):** set Source to "GitHub Actions" and use GitHub's own Pages actions at their current versions (these match Hugo's and Astro's docs):
  - `actions/checkout@v7` (v7.0.1, Jul 2026)
  - `actions/configure-pages@v6` (Mar 2026)
  - `actions/upload-pages-artifact@v5` (Apr 2026). Since v4 it skips dotfiles unless you set `include-hidden-files: true`.
  - `actions/deploy-pages@v5` (v5.0.1, Sep 2026)
  - Set permissions to `contents: read`, `pages: write`, `id-token: write`, with environment `github-pages`.
  - With Actions deploys, GitHub ignores the `CNAME` file; set the domain in Settings.
  - GitHub's starter workflow templates still show older versions (checkout@v4, configure-pages@v5, upload-pages-artifact@v3), so don't copy them unchanged.
- **Avoid the current pattern** of pushing to a `gh-pages` branch with a third-party action. It adds a dependency, needs a token that can write to the repo, and keeps an extra branch. `checkout@v4` is also an old release from before GitHub moved runners to Node 24. GitHub's changelog dated Node 20's removal from runners to Sep 23, 2026.
